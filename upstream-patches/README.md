# Installation-owned upstream patches

This directory is the reviewed, versioned source input for the enterprise-managed DeepSeek Harness runtime. It is build-time material owned by the Launcher repository; it is never shipped to an employee runtime.

`index.json` is the only patch-selection mechanism. A build must match one entry by the exact canonical repository, upstream tag, 40-character commit, and tree. The module additionally admits only hardcoded reviewed tag/commit tuples and verifies their exact tree, base `pnpm-lock.yaml` SHA-256, Git blob, byte length, and tuple-specific file counts. The builder then verifies the indexed manifest digest, deterministic zero-context generator contract, patch digest/byte/LF identity, every modified preimage Git blob, copies only the official `.git` metadata and tracked files into an independent link-free `OutDir` staging tree, applies the patch there, and verifies every reviewed changed path plus every postimage byte length, SHA-256, and Git blob before running any package-manager command. `scripts/New-ManagedSourcePatchBundle.ps1` rejects unknown tag/commit tuples, enforces the tuple-specific exact path/status set, rejects source or patch trailing whitespace, and proves byte-identical regeneration before writing the artifact.

Approved source contracts preserve `dsh-v0.1.1-rc.2`, `dsh-v0.1.2-alpha.1`, and `dsh-v0.1.2-alpha.3` only as historical reviewed bundles. Active admission is `dsh-v0.1.2-rc.1` at commit `a66e4702047846cdaa10c66c9d3df3951f5ea70d`, tree `27ab636bb3d77e698f5637e518db44ae1f61e262`, and 43 files (8 added, 35 modified). Its base lockfile must be SHA-256 `e12083149a77f790d39b64d018b6b8745c6a7aa95777ecb73e0a2f5ed5fdd0d9`, Git blob `4521b1bbf42de10ad2c19e85523b56661d19d8f7`, and 742793 bytes. The managed profile keeps JSONL persistence and does not mount `session-persistence-sqlite`; the Installation-layer guard is now wired into install, legacy migration, online update, ClientBootstrapper, and Launcher process-start admission, so evidence of that older optional persistent SQLite backend blocks automatic upgrade before state mutation and requires export with the old version. The guard is read-only, excludes employee `workspaces`, and never performs SQLite-to-JSONL migration.

An upstream update requires a new directory and index entry after rebase, security review, managed-composition digest regeneration, and focused tests. The builder deliberately refuses to apply an existing patch to an unknown tag, commit, or tree.

Employees receive only the signed complete runtime archive through the company update origin. They do not clone GitHub and do not receive Git, patch files, manifests, source paths, pnpm, npm, or build tooling.
